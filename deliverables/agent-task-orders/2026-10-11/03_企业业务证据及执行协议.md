# T3 企业业务事实整理与严格执行协议

## T3：企业视角的事实输入

本任务整理证据和问题，不作最终产品定位，不发起真实客户访谈/邮件或上传企业资料。
读取T1中业务目标、企业需求与用户原话；与T2官方企业案例分别标记来源。
用户的“更像企业SaaS/工程研发设计ERP”是方向，不能凭此虚构行业、客户、付费意愿或ROI。

至少核查以下候选场景；没有来源就hypothesis，不自动算作用户确认：
- 研发需求/缺陷 → 调研设计 → 代码 → 测试 → 审查 → 发布与变更追踪。
- 企业实施/咨询 → 多文档研究 → 方案/交付物 → 内部审查 → 客户交付。
- 内部业务流程 → 合同/采购/工单/报表 → 审批 → 业务系统回写。
记录任务的失败成本、审批责任、产物所有权、权限与现有系统。区分：
个人工程工具、团队研发管理、企业内部Agent平台、外部多租户SaaS。
不能把四种形态擅自合成一套“全部ERP功能”。

企业能力待调查清单（不是已确认应一次全做）：
租户/组织/项目/角色；SSO/OIDC/LDAP；对象级权限与凭证隔离；
预算/费用/配额；审批和操作留痕；数据驻留/导入/导出/删除/备份恢复；
连接器/事件/Webhook与幂等业务回写；工单/需求/资产/交付物版本关联；
CI/CD、灰度、升级与运维；任务质量评测、人员责任与人工接管；
企业安装/私有化/混合部署、计费及支持服务。
每项说明服务于哪个scenario_id，不能只堆术语。

## Codex最终优化方案的输出合同（审计后才能定稿）

最终文件须有：
1. 需求总账与竞品矩阵的验收SHA/时间、冲突裁决和不可验证项。
2. 产品定位、首批付费角色/行业/核心任务；已有证据与假设分开。
3. 企业用户从首次部署到完成首个真实业务任务的全流程。
4. 当前架构问题、目标架构、协议/数据/权限/模型/执行/恢复的唯一权威链。
5. 功能覆盖矩阵：Claude Code逐属性；LangGraph/Dify/Coze/FastGPT预定义核心集合；
   equivalence、partial、integration、not_supported分别标注。
6. Build / Reuse / Integrate / Buy候选决策，许可证/接口/版本/运维限制来源。
7. 企业价值：收益计算方法、基线、人工/模型/服务器/运维/迁移成本与敏感性。
   无客户或实际任务数据不得宣称企业已愿意付费或节省了多少。
8. 可检验的差异化优势，不以“功能更多”当收益。
9. 分期实施依赖图、优先级、工时区间和费用假设；没有资源事实不写确定排期。
10. 发布/回滚、验收/终止门、剩余风险与被否决方案理由。
11. 每个实现包的精确接口、来源需求ID、文件、步骤、测试命令与预期行为。
    不能在一页愿景后只写“按最佳实践补企业功能”。

## 执行 Agent 统一协议

“照方案执行”含义：不自行改产品目标、接口、权限、技术栈、预算和验收口径。
仍须进行必要的输入检查、错误处理和停止判断；不能靠不核对事实实现安全执行。
出现任务书没有给出唯一决定的情况，返回 DECISION_REQUIRED；受影响包停止，独立包继续。
验收100%指该包明确判据全部通过，不指软件从此无缺陷。
未完成记录 FAILED/BLOCKED/NOT_TESTED，不通过降低门槛或修改测试凑绿。

### 可复制的未来实现任务模板

# EXEC-<ID> <单一可验收功能> 实施任务
> 工作者按本任务逐项执行；需派子Agent时使用宿主可用的subagent-driven-development，
> 无子Agent工具时使用executing-plans；工具不可用就报告，不安装或假装已运行。

**Goal:** 一个具体用户行为的最终结果。
**Architecture:** 主审确定的组件、调用路径、数据权威与权限边界。
**Tech Stack:** 主审固定版本和依赖。
**Spec:** 已验收方案文件绝对路径、版本及SHA。
**Requirement IDs:** 已归一需求ID与竞品能力ID。

## Global Constraints
复制上位规格固定的性能/权限/成本/兼容/版本/输出限制。缺值时不实施，返回缺失项。

## Review Focus
填写输入丢失、跨租户、网络/磁盘失败、重试重复副作用、旧数据升级五类具体场景，
分别映射下面实际测试；不写泛泛的“考虑边界情况”。

## Files
Create/Modify/Test三个明确清单；每个文件只有一个当前写入者。
操作前记录git SHA和dirty diff；禁止覆盖别人已有改动。

## Interfaces
Consumes：精确API/函数签名/类型/错误码/权限/事务约定。
Produces：精确返回字段/事件/状态/数据迁移/输出命名。
Schema变化写出新增字段、默认值、索引、迁移顺序和升级/降级行为。
禁止用TBD、适当处理、自己选择最优方案等词下放决策。

## Steps
- [ ] 1. 确认输入、前置包提交与权限；不满足就BLOCKED。
- [ ] 2. 为规格规定的行为写失败测试，记录命令、退出码、失败原因。
- [ ] 3. 只改规定文件，按固定接口和已决算法实现。
- [ ] 4. 同一测试通过；跑影响面回归与真正关键E2E。
- [ ] 5. 对越权、不可逆副作用或持久化要求做负向/重启验证。
- [ ] 6. 比对需求判据逐条结果；未跑项单列，不当通过。
- [ ] 7. 仅提交本任务文件；保存原始证据、变更清单与可复现回滚步骤。
- [ ] 8. 返回主审评审，主审验收后才能合并/发版或解除后续包门禁。

## Acceptance
每条 GIVEN / WHEN / THEN 和固定阈值、证据来源与具体测试文件。
mock/provider-stub/纯函数与真实外部集成不能互换。
上线需真实费用/权限/隔离/恢复/升级证据；UI组件存在不算产品入口可用。

## Stop Conditions
权限不足/规格冲突/前置失败/成本到达包上限/副作用目标不明确/
第三方API与规格不符/3次同类失败/测试判据本身失效。
停止受影响步骤并回报，禁止绕过审批、扩大资源、放宽安全限制或删测试。

## Rollback
精确代码与数据目标；已发外部请求和费用不能用Git回滚，
必须说明补偿动作是否存在且是否需要人工批准。
